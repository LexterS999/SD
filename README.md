# Парсер Telegram-каналов и протоколов

Проект собирает профили VLESS / VMess / Trojan / SS / SSR / TUIC / Hysteria из внешних подписок и публичных Telegram-каналов, выполняет жёсткую дедупликацию и формирует итоговый `protocols.txt` только из уникальных профилей.

## Что изменено

- Telegram-каналы обрабатываются только за последние 7 дней.
- Реестр `protocols.txt` работает как 7-дневное окно:
  - в течение окна новые профили добавляются;
  - дубли запрещены;
  - после 7 дней реестр полностью пересобирается.
- Внедрена комплексная дедупликация:
  - по каноническому виду профиля;
  - по identity-ключу `protocol + ip + port + credential`.
- Запрещены endpoint'ы, где вместо IP используется домен или IPv6.
- Разрешены только IPv4 endpoint'ы.
- Добавлена быстрая speed-оценка профилей с использованием сценария малого 100KB test file.
- Ускоренные профили получают дополнительный вес и поднимаются выше при достаточном базовом скоре.
- Добавлен подробный `config.py` на русском языке.

## Быстрый запуск

```bash
pip install -r requirements.txt
python3 parser.py
```

## Основные файлы

- `parser.py` — основной скрипт.
- `config.py` — все настройки с пояснениями на русском.
- `input.txt` — список входных подписок.
- `output/protocols.txt` — итоговый список уникальных профилей.
- `output/protocols_state.json` — внутреннее состояние 7-дневного окна.
- `output/best_channels.txt` — лучшие Telegram-каналы.
- `output/bad_channels.txt` — плохие Telegram-каналы.
- `output/stats.json` — статистика запуска.

## Важное замечание по speed-test

Для массовой и быстрой оценки больших списков профилей по умолчанию используется быстрый сетевой probe, нормализованный под сценарий малого test-file. Это сделано специально, чтобы проверка десятков тысяч профилей не превращалась в многосотминутный прогон.

Если позже понадобится, проект можно дорасширить до полноценной проверки трафика через внешний proxy-core (sing-box/xray), но для больших подборок это существенно тяжелее и медленнее.
